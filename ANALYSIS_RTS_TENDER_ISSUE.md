# Анализ проблемы с парсером RTS-Tender

## Описание проблемы
Парсер RTS-Tender выдает сообщение: "Закупки найдены, но не удалось извлечь данные. Возможно, требуется анализ структуры страницы после обхода защиты."

## Причина проблемы
Проблема возникает в методе `parse` класса `RtsTenderParser` в файле `app/services/parsers/rts_tender.py`. После успешного обхода Cloudflare защиты и получения HTML-кода страницы, парсер не может извлечь нужные данные, потому что:

1. Структура HTML-страницы после обхода защиты может отличаться от ожидаемой
2. Селекторы, используемые для извлечения данных, не соответствуют реальной структуре
3. Контент загружается асинхронно через JavaScript, и на момент парсинга он еще не доступен

## Текущая логика в коде

### В `app/services/parsers/rts_tender.py`:
- Строка 140-146: Если не удается извлечь ни одного результата, возвращается сообщение об ошибке
- Строка 74-114: Попытка найти элементы с закупками с помощью различных селекторов
- Строка 116-139: Обработка найденных контейнеров

### В `app/services/scraper_engine.py`:
- Строка 96-112: Используется специальная логика для RTS-Tender с cloudscraper и Selenium
- Строка 321-373: Метод `_run_cloudscraper_parser` для обхода Cloudflare
- Строка 447-620: Метод `_run_selenium_parser` с расширенными настройками для обхода защиты

## Возможные причины неудачного извлечения данных:

1. **Изменение структуры сайта**: После обхода защиты сайт мог изменить свою HTML-структуру
2. **Асинхронная загрузка контента**: Данные загружаются через JavaScript после основной загрузки страницы
3. **Недостаточное ожидание**: Браузер переходит к парсингу до того, как контент полностью загрузится
4. **Динамическая генерация контента**: Содержимое генерируется динамически и не представлено в исходном HTML

## Решение проблемы

### Вариант 1: Улучшение ожидания контента в Selenium
```python
# В методе _run_selenium_parser добавить ожидание конкретных элементов
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.common.by import By

# Ждать появление элементов с закупками
try:
    WebDriverWait(driver, 20).until(
        EC.presence_of_element_located((By.CSS_SELECTOR, ".tender-item, .procedure-item, .auction-item"))
    )
except TimeoutException:
    logger.warning("Elements not found, trying alternative selectors...")
```

### Вариант 2: Обновление селекторов в парсере
Добавить больше возможных селекторов для обнаружения элементов закупок:
```python
selectors_to_try = [
    '.tender-item',
    '.procedure-item', 
    '.auction-item',
    '.result-item',
    '.search-result',
    'tr.tender-row',
    '[data-tender]',
    '.tender-card',
    '.lot-item',
    '.purchase-item',
    '.trade-item'
]
```

### Вариант 3: Проверка состояния документа перед парсингом
В методе `parse` добавить проверку, содержит ли HTML реальные данные закупок:
```python
# Проверить, содержит ли страница ожидаемые элементы
if "лот" in html.lower() or "тендер" in html.lower() or "закупк" in html.lower():
    # Есть признаки наличия закупок, продолжить парсинг
else:
    # Страница может быть промежуточной или с ошибкой
    return [ReviewItem(
        text="Обнаружена страница без данных о закупках. Возможно, защита не полностью снята.",
        author="Техническая информация", 
        rating="Недоступно"
    )]
```
